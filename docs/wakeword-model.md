# Модель активации «Джарвис»

## Почему модели нет в репозитории

Модель головы обучается на записях конкретного голоса и комнаты. Публиковать
её — значит публиковать производные персональных записей. Кроме того, часть
инструментов обучения и весов имеет собственные лицензии. Поэтому в
репозитории лежит только feature-backbone (`assets/oww.bin`) и код; модель
устанавливается отдельно.

Без модели `wakeword.enabled = true` не пройдёт проверку конфигурации.
Варианты:

1. импортировать существующую модель станции;
2. обучить новую;
3. временно выключить активацию (`enabled = false`) и запускать диалог
   кнопкой — это не полноценный сценарий, но полезно для отладки остального
   тракта.

## Формат

`wakeword.json`:

```json
{
  "name": "джарвис",
  "threshold": 0.99,
  "created": "2026-11-16",
  "head": {
    "w1": [0.0, "..."],
    "b1": ["..."],
    "w2": ["..."],
    "b2": ["..."],
    "w3": ["..."],
    "b3": [0.0]
  }
}
```

Размеры: `w1` = 96×24, `b1` = 24, `w2` = (16×24)×24, `b2` = 24,
`w3` = 24, `b3` = 1. Голова получает 16 последовательных эмбеддингов по 96
(окно 1,28 с) и выдаёт вероятность. Лишние поля обучения (`takes`,
`recall`, …) игнорируются.

`assets/oww.bin` — контейнер `OWW1`: мел-фильтры и веса эмбеддингов
openWakeWord. Формат читается строго, обрезанный файл отвергается.

Детектор требует два подряд окна выше порога (80 мс задержки) и затем
рефрактерный период `refractory_ms`. Порог = `threshold` из модели +
`sensitivity`, ограничен `0.05..0.999`.

## Импорт существующей модели

Если на колонке осталась прежняя лабораторная установка:

```bash
# установщик сделает это сам, если файл есть
python3 installer/jarvis_install.py --ssh-host station install
# или явно:
python3 installer/jarvis_install.py --ssh-host station install \
  --wakeword-model ./wakeword.json
```

Установщик копирует `/data/opt/wakeword/model.json` в
`/data/jarvis/models/wakeword.json`, только если целевого файла нет.
Проверка:

```bash
/data/jarvis/current/jarvisctl --config /data/jarvis/config.toml wake-test take.wav
```

## Обучение

Модель совместима по формату с тренировщиком
[tangenx/station-wakeword](https://github.com/tangenx/station-wakeword),
который использовался в лаборатории. Код тренировщика в этот репозиторий не
переносился (у upstream нет файла лицензии); используйте его отдельно,
соблюдая условия автора.

Схема, проверенная в лаборатории:

1. записать 60–80 произнесений «Джарвис» в той же комнате и тем же трактом,
   включая тихую речь, шёпот и расстояние 3–4 м;
2. добавить комнатный фон и отрицательные примеры (обычная речь, близкие
   имена);
3. исключить каждое третье произнесение из обучения — проверочная серия;
4. обучить голову, оценить recall и ложные срабатывания;
5. прогнать `wake-test` на отложенных записях;
6. подобрать `sensitivity`/`gain`, не снижая порог без проверки фона.

Синтетические записи (Piper) помогают разнообразию, но не заменяют реальный
микрофон. Шёпот имеет динамический диапазон 11–15 дБ; энергетический VAD
тренировщика должен брать уже обрезанный фрагмент целиком, иначе тихие
записи молча теряются.

## Порог и усиление

- `threshold` в модели — базовый; `[wakeword] threshold` переопределяет его;
- `sensitivity` отрицательный — чаще срабатывания, положительный — реже;
- `gain` (по умолчанию 32) компенсирует уровень `vqe_0`; слишком большой
  клиппирует и ломает эмбеддинги;
- `refractory_ms` защищает от повторного срабатывания на хвосте слова.

Меняйте по одному параметру и проверяйте на записях, которых не было в
обучении.
