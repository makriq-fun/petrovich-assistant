# Станция Мини 2

Профиль `station-mini2` (`HardwareProfile`). Данные основаны на документации
проекта Pulsar и прежней лабораторной станции. Установка на `station-mini2`
выполнялась; полный сценарий на конкретной ревизии прошивки всё равно нужно
принимать на устройстве.

## Звук

- Захват: ALSA `default`, 48 кГц, 6 каналов S16_LE.
- Каналы 0–3 — PDM-микрофоны, 4–5 — петля TDM усилителя (аппаратный
  референс). Это позволяет подавлять эхо собственным NLMS даже без VQE.
- Вывод: ALSA `default` (softvol Master над dmix), 48 кГц, stereo.
- `default` использует общий `dmix` на SysV IPC. Если процесс, создавший
  сегмент (сервер `dmix`), умер, новый клиент навсегда застревает в `poll`
  на первом `write`. Демон при старте удаляет такие устаревшие сегменты;
  иначе помогает только `ipcrm` или перезагрузка.
- Громкость: `amixer -D default sset Master N%`; кривая линейна в процентах.
- VQE: пресет `yandexmini_2`, библиотека
  `/system/vendor/quasar/libs/libyandex_evil.so`, модели
  `/system/vendor/quasar/vqe_models`. `libtflite.so` и `libiconv.so`
  подгружаются заранее из каталога прошивки.
- Выход VQE `omni` (тип 6) — 16 кГц, используется как канал распознавания.
- Если VQE недоступен: среднее микрофонов → КИХ 48→16 кГц → NLMS по
  референсу → шумовой затвор. Качество на реальной комнате не измерялось.

Проверка на колонке:

```bash
/data/petrovich/current/petrovichctl --config /data/petrovich/config.toml doctor
# войти в логи:
tail -f /data/petrovich/log/petrovichd.log
```

В журнале при старте: `VQE 'yandexmini_2': N входных кадров -> M выходных`
или предупреждение о переходе на собственный DSP.

## Светодиоды

6 RGB-пикселей через sysfs:

```
/sys/class/leds/mini2:red:ring1/brightness
...
/sys/class/leds/mini2:blue:ring6/brightness
```

Яркость 0–255, ограничение `hardware.led_brightness`. Анимации считаются по
времени и обновляются 50 раз в секунду; цвет между кадрами интерполируется,
поэтому переходы состояний не рывками. Слушает — синее дыхание (2,4 с),
думает — бегущая точка с хвостом, говорит — зелёный пульс, ошибка — красный,
мут — тусклый красный, громкость — дуга. События «услышал», «готово»,
«остановлено», «диалог очищен» и таймер добавляют короткую волну поверх
состояния. Запись в sysfs идёт только при изменении значения.

Если файлов нет, демон пишет предупреждение и работает без кольца.

## Часы

На части ревизий панель отсутствует. Семь сегментов на цифру:

```
/sys/class/leds/mini2:white:clockA1/brightness   # A..G, позиции 1..4
/sys/class/leds/mini2:white:clockPLUS1/brightness
/sys/class/leds/mini2:white:clockPLUS2/brightness
```

Вспомогательные `DEGREE` и `MINUS` гасятся. Часы показывают время с плавно
мигающим двоеточием (яркость меняется по косинусу, а не рывком раз в
секунду). При активном таймере — `MM:SS`, после срабатывания возвращаются к
времени. Во время размышления по сегментам бежит точка-спиннер; после ответа
кратко горит `8888`, при остановке — `----`, после очистки — `0000`, при
ошибке — `EEEE`. Яркость — значение сегмента (не общий current). Если панель
не найдена, часы отключаются, демон продолжает работу.

## Кнопки

evdev-устройство `sar0_pad0`:

- `KEY_VOICECOMMAND` 582 / настроенный `action_key` — начать/отменить/прервать;
- `KEY_VOLUMEUP` 115, `KEY_VOLUMEDOWN` 114 — шаг громкости;
- `KEY_MUTE` 113, если есть — программный мут.

Узел ищется в `/proc/bus/input/devices` по имени; путь не угадывается.
События читаются блокирующим потоком, повторные `value=2` игнорируются.

## Мут микрофонов

Аппаратный переключатель на GPIOZ_3 (глобальный 414), активный низкий
уровень. Демон только читает
`/sys/class/gpio/gpio414/value` раз в 400 мс; экспорт и настройку не делает.
`0` — микрофоны выключены: активация и VAD не работают, звук останавливается,
кольцо красное. Переопределение — `hardware.mic_mute_gpio`.

## Датчик освещённости

На части ревизий стоит `ltr308als01` (IIO). Демон ищет его в
`/sys/bus/iio/devices/iio:device*/name` и читает `in_intensity_input`;
люксы = сырое значение / 120. Если драйвер отдаёт `in_illuminance_input`,
значение уже в люксах.

При `hardware.auto_brightness = true` яркость кольца и часов плавно
подстраивается по логарифмической шкале, но не ниже
`hardware.night_brightness` от максимума. Путь можно переопределить в
`hardware.light_sensor` (каталог IIO или файл значения). Если датчика нет,
используется фиксированная яркость, а демон продолжает работу.

Проверка:

```bash
/data/petrovich/current/petrovichctl --config /data/petrovich/config.toml light-test
```

## Ограничения

- Часы и датчик освещённости есть не на всех экземплярах; код это учитывает.
- Прошивка может отличаться набором каналов VQE и путями; при несовпадении
  используйте `vqe = "auto"` и смотрите журнал.
- Уровень `vqe_0` у моделей разный; усиление детектора `gain` подбирается
  записью и `wake-test`, а не по паспорту.
- Аппаратные проверки обязательны; см. [testing.md](testing.md).
