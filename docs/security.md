# Безопасность и приватность

## Модель угроз

Демон работает под root на колонке. Это не песочница для вредоносного
процесса: root уже имеет доступ ко всему. Задача — не дать **языковой модели**
и внешнему контенту неограниченный доступ к системе.

- LLM не получает оболочку. Инструменты вызываются только по имени и только
  из белого списка `[tools] enabled`.
- Каждый инструмент проверяет аргументы и имеет тайм-аут.
- `run_code` выключен, пока администратор не задаст `sandbox_command`.
  Даже тогда это argv-команда, а не свободная строка shell; код передаётся
  одним аргументом.
- Веб-контент считается недоверенным. Инструмент возвращает текст, а не
  исполняет найденные команды. Модель может попытаться вызвать инструмент по
  инструкции со страницы — поэтому опасные инструменты по умолчанию
  отсутствуют.

## Секреты

- `secrets.env` читается только с правами `0600`/`0400`; иначе запуск
  прекращается.
- Значения не реализуют `Debug`, не логируются; в сообщениях об ошибках
  длинные токены заменяются на `[скрыто]`.
- Секреты не входят в репозиторий и в выпускной tar.
- Владелец файла должен быть root (проверка прав, не UID, чтобы не ломать
  нестандартные образы).

## Сеть

- HTTPS обязателен, кроме loopback для локальных сервисов.
- Проверка сертификатов rustls включена; опции отключения нет.
- Тайм-ауты соединения и запроса, ограничение размера ответов.
- STT/TTS/LLM не перенаправляют запросы на произвольные хосты: URL берётся
  из конфигурации, не из ответа модели.
- `web_fetch`: только HTTPS (или HTTP при `web_allow_private = true`),
  запрещены учётные данные в URL, `localhost`, `.local`, `.internal`,
  частные, loopback, link-local и служебные IP. Редиректы отключены, чтобы
  проверенный адрес не подменился. DNS разрешается до запроса; остаточный
  риск DNS-rebinding не устранён полностью — не включайте `web_fetch` в
  среде, где это критично.
- SearXNG может быть на loopback; ответ ограничен `web_max_bytes`.
- Погода: Open-Meteo или совместимый endpoint; координаты из конфигурации.

## Независимость от Яндекса

Установщик:

1. останавливает Quasar вызовом `/system/vendor/quasar/q stop`;
2. заменяет init-скрипты, в имени которых есть `quasar`, шимом: при
   существовании `/data/jarvis/enabled` они завершаются, не запуская стек;
3. оригиналы сохраняет в `/data/jarvis/backups/quasar-init/*.orig`;
4. ставит `S99jarvis`, который запускает только супервизор помощника.

При падении jarvisd супервизор перезапускает его до 5 раз, затем остаётся
остановленным. Quasar не запускается как запасной вариант. `jarvisctl doctor`
проверяет, что `maind`/`quasar_launcher2` не работают.

DNS и NTP:

- `/etc/resolv.conf` должен указывать на выбранные независимые DNS; установщик
  его не переписывает, чтобы не сломать сеть неожиданно;
- NTP настраивается отдельно (`ntpd`/chrony) на выбранные серверы;
- `jarvisctl doctor` проверяет разрешение доменов из
  `privacy.yandex_hosts`. Предупреждение означает, что DNS ещё отдаёт
  адреса Яндекса; это не доказывает трафик, но требует разбора.

Полное доказательство отсутствия обращений требует перехвата трафика и
аудита прошивки; диагностика этого не заменяет.

## Приватность данных

- Активация и VAD — локально; аудио не пишется на диск.
- В STT уходит только запись фразы после активации/продолжения.
- В LLM уходит распознанный текст и история диалога (в пределах лимитов).
- В TTS уходит текст ответа.
- Провайдеры видят эти данные; выбирайте локальные сервисы, если это
  неприемлемо.
- Журнал содержит распознанный текст и ответы; доступ к
  `/data/jarvis/log/jarvisd.log` должен быть только у root.

## Ограничения

- Root-процесс и прошивочные библиотеки не изолированы.
- `bwrap`/контейнер на ARMv7 может отсутствовать; тогда `run_code` надо
  оставить выключенным.
- Модель активации можно обмануть; это не аутентификация.
- Инструменты выполняются от имени root, если демон запущен от root.
- Обновления выпусков не подписаны; проверяйте SHA256 и источник.
