# Проверка и ограничения

## Автоматические проверки

```bash
cargo test --workspace
cargo clippy --workspace --all-targets -- -D warnings
python3 -m unittest discover -s installer/tests -v
```

На момент написания: **281 тест** в workspace (4 сетевых YouTube-теста
игнорируются) и 10 Python-тестов установщика.
Что покрыто:

- конфигурация: значения по умолчанию, неизвестные ключи, каналы, URL,
  права секретов, `command`-провайдеры;
- история: лимиты ходов/символов, сохранение пары `tool_call`→`tool`,
  TTL, сброс;
- память: дедупликация, лимиты, права `0600`, перезагрузка, удаление по
  подстроке и очистка, бюджет промпта и внедрение в системное сообщение;
- WAV: PCM16, stereo→mono, обрезанные файлы, WAVE_FORMAT_EXTENSIBLE,
  защита от огромной длины чанка;
- аудио: децимация 48→16 кГц и подавление алиасинга, линейный ресемплер,
  NLMS на синтетическом эхе, адаптивный VAD (пауза внутри фразы, короткая
  команда, шум, максимальная длина), пре-ролл, fallback-тракт;
- активация: мел-фронтенд, streaming-эмбеддинги, независимость от разбиения
  потока, форма головы, порог/рефрактерность, microWakeWord-манифест;
- провайдеры: SSE (включая разрыв чанков), накопление аргументов tool calls,
  non-stream, ошибки HTTP, multipart STT, PCM/WAV TTS, локальные команды;
- текст: разбиение на фразы, сокращения, markdown, вырезание fenced-кода и
  строк кода, отказ «Код не пишу.» при кодовом ответе;
- озвучка: кэш повторяющихся фраз, вытеснение, воспроизведение из кэша,
  предзагрузка следующей фразы, приглушение музыки на время речи;
- инструменты: белый список, тайм-ауты, параллельные вызовы, таймеры и
  будильники с персистентностью/повтором/отложением, громкость, Spotify
  (разбор результатов и выбор последнего выпуска), YouTube-поиск и очередь,
  эмоции, Tavily, погода по городу из памяти, сахар из Nightscout,
  умный дом Tuya (QR-вход, подпись облака, mock-устройства 3.3/3.5,
  состояние, команды и запрет опасных категорий), отключённая песочница;
- железо и экран: sysfs-запись LED/часов, погода/глюкоза/таймер/позиция,
  анимации эмоций без букв, плавная яркость, поиск evdev, разбор
  `input_event`, дребезг Action, GPIO-мут, датчик `ltr308`, автояркость;
- ByeDPI: разбор пресетов ByeByeDPI, SNI в ClientHello, фильтр доменов
  YouTube, целостность TCP-потока после split/OOB/disorder, SOCKS5-туннель;
  живой прогон на хосте выбрал `-d 1 -s 1` и декодировал первый DASH-пакет
  `jNQXAC9IVRw` через локальный прокси;
- звуки: длина, нулевые края, отсутствие клиппинга и резких фронтов,
  компенсация громкости при низком Master;
- сеть: HTTP CONNECT-мост к SOCKS5 (полный обмен с эхо-сервером), разбор
  CONNECT, IPv4/домен/IPv6 и SOCKS5-аутентификация;
- быстрые команды: разбор фраз и ID модели, приоритет глобального стопа
  (`Thinking` → ассистент, музыка → музыка, пассивный `Listening` → ассистент);
  без AEC громкость/переключение не срабатывают от собственной речи или музыки,
  «стоп» остаётся доступен;
- демон: полный ход STT→LLM→TTS на mock-сервере, включая tool call;
- установщик: определение модели, выбор отката, шим Quasar, валидация версии;
- диагностика: разбор IPv4/IPv6 из `/proc/net/tcp{,6}`.

## Ресурсы (замеры)

Замеры на хосте x86_64 и ARMv7 под `qemu-arm`; ALSA-вход заменён `null`,
поэтому загрузка CPU не показательная. Абсолютные значения на колонке нужно
перепроверить `petrovichctl status` и `top`.

| Показатель | До | После |
|---|---|---|
| ARMv7 `petrovichd` | 5,8 МБ | 12 МБ |
| установочный `tar.gz` (host) | 6,4 МБ (0.2.4) | 9,9 МБ |
| RSS в простое, ARMv7/qemu | 32,2 МБ | 36,1 МБ (+3,9 МБ) |
| RSS в простое, host | — | 10,2 МБ, стабильно 30 с |

Рост даёт librespot и второй Symphonia (Spotify декодирует Ogg/Vorbis,
YouTube — AAC). В простое без учётных данных Spotify не запускает сессию,
ByeDPI-прокси и декодеры не создаются. Кэш librespot ограничен 16 МБ, TTS —
32 фразами, журнал супервизора ротируется при старте при размере >2 МБ.
Пиковая RAM при воспроизведении Spotify/YouTube на устройстве не измерена:
для этого нужны реальные сеть, ALSA и аккаунт.

## Совместимость и качество активации

- openWakeWord-пайплайн: тест `crates/petrovich-wakeword/tests/parity.rs` — те же
  16 окон на детерминированном тоне, расхождение эмбеддингов < 0.25 (разный
  порядок f32-сумм). На реальных записях старый детектор давал те же
  срабатывания; это проверка пайплайна, не качества в новой комнате.
- Встроенная голова «Петрович» загружается на колонке, `--check-config`
  проходит; в журнале фиксируется `активация: «petrovich», порог 0.500`.
  Качество и ложные срабатывания на конкретной комнате в репозитории не
  измерялись.
- microWakeWord-бэкенд остаётся для моделей, переданных через
  `--wakeword-model`; на хосте тестируется разбор манифеста и загрузка, не
  сам инференс.

Это доказывает совместимость пайплайна, но не заменяет живую проверку.

## Проверено на колонке 20.11.2026

- `doctor`: VAD, PDM Gain 30, общий прокси, VQE, ALSA, кнопки, часы — без FAIL.
- STT, LLM, TTS, погода и Tavily прошли через `socks5h://127.0.0.1:1080`.
- Spotify Connect авторизовался и зарегистрировал устройство «Петрович» без
  запуска воспроизведения.
- Встроенный ByeDPI выбрал сохранённую стратегию и декодировал первый
  аудиопакет `jNQXAC9IVRw`.
- RSS после перезапуска — 29,6 МБ, установочный ARMv7-пакет — 9,3 МБ.
- CPU демона в покое — около одного ядра из четырёх: основной поток занят
  непрерывной обработкой VQE/активации. Это цена always-on тракта, не утечка.

## Что **не** проверено

Полная приёмка на физической колонке в репозитории не зафиксирована.
Не проверены:

- захват и вывод ALSA на прошивке, реальный VQE-пресет, задержки;
- качество эха/шума в комнате, ложные активации на бытовом фоне;
- Spotify Connect на живом аккаунте: видимость, поиск Web API, декодирование
  librespot, перемотка, очередь и таймер сна;
- встроенный ByeDPI на реальной блокировке: выбор стратегии, устойчивость
  медиапотока и переключение при деградации;
- YouTube на устройстве: длинные видео, сетевые обрывы, позиция после
  перезапуска;
- светодиоды и часы на конкретной ревизии (панель есть не у всех);
- evdev-коды и GPIO-мут на конкретном экземпляре;
- полный сценарий установки через ADB/SSH и поведение при обрыве питания;
- перезагрузки, длительная работа, утечки памяти;
- реальные STT/LLM/TTS API (тесты используют mock);
- загрузка command spotter и его срабатывания на живой речи: ложные
  срабатывания под TTS/музыку, порог и задержка;
- отсутствие трафика Яндекса (диагностика только косвенная);
- восстановление штатной прошивки.

Эти пункты обязательны перед заявлением «работает на станции».

## Проверка на колонке

```bash
/data/petrovich/current/petrovichctl --config /data/petrovich/config.toml doctor
/data/petrovich/current/petrovichctl --config /data/petrovich/config.toml status
/data/petrovich/current/petrovichctl --config /data/petrovich/config.toml wake-test take.wav
/data/petrovich/current/petrovichctl --config /data/petrovich/config.toml commands-test command.wav
/data/petrovich/current/petrovichctl --config /data/petrovich/config.toml light-test
tail -f /data/petrovich/log/petrovichd.log
```

`wake-test` принимает WAV PCM16, приводит к 16 кГц/моно и печатает score по
шагам. Для калибровки используйте записи из той же комнаты и тот же тракт
(`vqe_0`/микрофоны), иначе порог будет неверным.
Загрузку command spotter видно по строке `быстрые команды:` в журнале; если
модели нет, там будет предупреждение `быстрые команды недоступны`.
`commands-test` принимает WAV любой частоты/каналов, приводит к 16 кГц/моно и
печатает `команда: Next` и т.п.; это проверка модели и ABI без демона.

Сценарий приёмки:

| Проверка | Ожидание |
|---|---|
| слово активации | мягкий сигнал, синее кольцо, Listening |
| вопрос | распознан, слышен «услышал», ответ озвучен |
| конец ответа | без задержки и финального сигнала, зелёная волна, `8888` на часах |
| длинная фраза с паузами | пауза 0,5–0,9 с внутри предложения не обрывает запрос |
| «Петрович, какая погода?» | пре-ролл сохраняет начало сразу после имени |
| составное поручение | подкаст + таймер + будильник; ошибка одного не мешает другим |
| отмена поручения | «стоп»/кнопка прекращает инструменты и озвучку |
| «стоп» / кнопка | сигнал остановки, `----` на часах, возврат в ожидание |
| сброс диалога | сигнал очистки, `0000` на часах |
| датчик света | `light-test` показывает люксы; яркость меняется плавно |
| уточнение без имени | новый ответ в пределах follow-up |
| слово активации во время ответа | звук прерван, новое слушание |
| кнопка во время ответа | ответ оборван, возврат в ожидание |
| громкость кнопками | шаг 5%, кольцо показывает уровень |
| мут | красное кольцо, активация не срабатывает |
| таймер | звонок и озвучка; часы показывают остаток; после перезапуска жив |
| будильник | звонок до dismiss/snooze, повтор по дням, настройки после перезагрузки |
| эмоция | анимация «глаз/улыбки» на часах, цвет кольца, мягкий звук |
| громкость голосом | часы показывают 0..100 без двоеточия |
| Spotify Connect | «Петрович» виден в приложении до включения музыки |
| Spotify поиск | «включи последний выпуск подкаста X» запускает нужный выпуск |
| Spotify управление | pause/resume/next/previous/seek/queue/sleep |
| YouTube поиск | десятки результатов, вторая страница, метаданные и id |
| YouTube детали | субтитры и комментарии для доступного видео |
| YouTube управление | seek, таймкод, очередь, позиция после перезапуска, sleep |
| ByeDPI | в журнале выбрана стратегия, медиапоток декодируется; смена при сбое |
| быстрые команды | без активации: «дальше», «назад», «громче», «тише»; в журнале `быстрая команда` |
| «пауза» без активации | останавливает ассистента в `Thinking`, а при звучащей музыке — музыку |
| тишина после активации | короткий сигнал окончания прослушивания |
| погода без города | первый раз уточняет, запоминает; при переезде обновляет |
| погода в городе | «погода в Казани» без координат в конфиге |
| перезагрузка | petrovichd поднялся, Алиса не отвечает, таймеры/будильники на месте |
| `ps` | нет `maind`, `quasar_launcher2` |
| `doctor` | нет FAIL; WARN разобраны |

## CI

GitHub Actions:

- `fmt`, `clippy -D warnings`, `cargo test --workspace`;
- Python-тесты установщика;
- кросс-сборка `armv7-unknown-linux-gnueabihf` (glibc 2.23) через `cross`;
- выпуск по тегу `v*` с tar и `SHA256SUMS`.

Кросс-сборка в CI не равна проверке на устройстве. В этом окружении
`armv7-unknown-linux-gnueabihf` собран в контейнере с glibc 2.23; `petrovichd --version` и `--check-config` прошли под `qemu-arm`.
