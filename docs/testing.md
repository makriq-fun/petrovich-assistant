# Проверка и ограничения

## Автоматические проверки

```bash
cargo test --workspace
cargo clippy --workspace --all-targets -- -D warnings
python3 -m unittest discover -s installer/tests -v
```

На момент написания: **110 тестов** в workspace и 5 Python-тестов установщика.
Что покрыто:

- конфигурация: значения по умолчанию, неизвестные ключи, каналы, URL,
  права секретов, `command`-провайдеры;
- история: лимиты ходов/символов, сохранение пары `tool_call`→`tool`,
  TTL, сброс;
- WAV: PCM16, stereo→mono, обрезанные файлы, WAVE_FORMAT_EXTENSIBLE;
- аудио: децимация 48→16 кГц и подавление алиасинга, линейный ресемплер,
  NLMS на синтетическом эхе, VAD на шуме/тоне/тишине, fallback-тракт;
- активация: мел-фронтенд, streaming-эмбеддинги, независимость от разбиения
  потока, форма головы, порог/рефрактерность;
- провайдеры: SSE (включая разрыв чанков), накопление аргументов tool calls,
  non-stream, ошибки HTTP, multipart STT, PCM/WAV TTS, локальные команды;
- инструменты: белый список, тайм-ауты, таймеры, громкость, музыка, веб,
  погода, отключённая песочница;
- железо: sysfs-запись LED/часов, поиск evdev, разбор `input_event`, GPIO-мут;
- демон: полный ход STT→LLM→TTS на mock-сервере, включая tool call;
- установщик: определение модели, выбор отката, шим Quasar, валидация версии;
- диагностика: разбор IPv4/IPv6 из `/proc/net/tcp{,6}`.

## Совместимость с эталоном активации

Rust-порт feature-backbone сравнивался с независимой Go-реализацией,
использованной в лаборатории:

- тест `crates/jarvis-wakeword/tests/parity.rs` — те же 16 окон на
  детерминированном тоне, расхождение эмбеддингов < 0.25 (разный порядок
  f32-сумм);
- на четырёх реальных записях «Джарвис» детектор дал те же срабатывания
  (3280, 3120, 3200, 3200 мс) и те же пиковые оценки; расхождение score
  практически нулевое;
- модель головы при этом бралась из локальной лабораторной установки и в
  репозиторий не входит.

Это доказывает совместимость пайплайна, но не качество на новой комнате и не
заменяет живую проверку.

## Что **не** проверено

В этом репозитории нет физической колонки. Поэтому не проверены:

- захват и вывод ALSA на прошивке, реальный VQE-пресет, задержки;
- качество эха/шума в комнате, ложные активации на бытовом фоне;
- светодиоды и часы на конкретной ревизии (панель есть не у всех);
- evdev-коды и GPIO-мут на конкретном экземпляре;
- установка через ADB/SSH на живое устройство, поведение при обрыве питания;
- перезагрузки, длительная работа, утечки памяти;
- реальные STT/LLM/TTS API (тесты используют mock);
- отсутствие трафика Яндекса (диагностика только косвенная);
- восстановление штатной прошивки.

Эти пункты обязательны перед заявлением «работает на станции».

## Проверка на колонке

```bash
/data/jarvis/current/jarvisctl --config /data/jarvis/config.toml doctor
/data/jarvis/current/jarvisctl --config /data/jarvis/config.toml status
/data/jarvis/current/jarvisctl --config /data/jarvis/config.toml wake-test take.wav
tail -f /data/jarvis/log/jarvisd.log
```

`wake-test` принимает WAV PCM16, приводит к 16 кГц/моно и печатает score по
шагам. Для калибровки используйте записи из той же комнаты и тот же тракт
(`vqe_0`/микрофоны), иначе порог будет неверным.

Сценарий приёмки:

| Проверка | Ожидание |
|---|---|
| «Джарвис» | сигнал, синее кольцо,Listening |
| вопрос | распознан, ответ озвучен |
| уточнение без имени | новый ответ в пределах follow-up |
| «Джарвис» во время ответа | звук прерван, новое слушание |
| громкость кнопками | шаг 5%, кольцо показывает уровень |
| мут | красное кольцо, активация не срабатывает |
| таймер | звонок и озвучка, часы MM:SS |
| перезагрузка | jarvisd поднялся, Алиса не отвечает |
| `ps` | нет `maind`, `quasar_launcher2` |
| `doctor` | нет FAIL; WARN разобраны |

## CI

GitHub Actions:

- `fmt`, `clippy -D warnings`, `cargo test --workspace`;
- Python-тесты установщика;
- кросс-сборка `armv7-unknown-linux-musleabihf` через `cross`;
- выпуск по тегу `v*` с tar и `SHA256SUMS`.

Кросс-сборка в CI не равна проверке на устройстве. В этом окружении
статический `armv7-unknown-linux-musleabihf` собран в контейнере с musl-
тулчейном; `jarvisd --version` и `--check-config` прошли под `qemu-arm`.
