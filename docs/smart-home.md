# Умный дом Tuya

Петрович управляет устройствами Tuya Smart / Smart Life напрямую по локальной
сети. Облако нужно один раз — чтобы получить список устройств и локальные
ключи. После этого повседневные команды не обращаются в интернет, не требуют
Home Assistant, отдельного сервиса или собственного проекта в Tuya Developer
Platform.

## Как это устроено

1. `petrovichctl smart-home login` получает QR-код через публичный Client ID
   интеграции Home Assistant и ждёт подтверждения в приложении Tuya Smart или
   Smart Life.
2. После входа Петрович забирает дома, комнаты, устройства, их `local_key`,
   версию локального протокола и карту DP (какие функции и состояния есть у
   устройства).
3. Сессия и ключи сохраняются только на колонке, в
   `<state_dir>/smart_home/`, с правами `0600`. В `config.toml`, репозиторий и
   журналы секреты не попадают.
4. Демон сам находит устройства по локальной сети, определяет протокол
   (3.1–3.5), кэширует IP и версию и переподключается после перезагрузки
   колонки, смены IP или временной недоступности устройства.
5. Инструмент `smart_home` даёт LLM только высокоуровневые действия: список,
   состояние, включить/выключить, яркость, цвет, температура света, режим,
   температура климата, вентилятор, положение штор. Произвольных DP и
   произвольных ID устройств в схеме инструмента нет.

## Первичное подключение

На компьютере, где доступен `petrovichctl`:

```bash
petrovichctl smart-home login --scheme smartlife
# для аккаунта Tuya Smart:
petrovichctl smart-home login --scheme tuyaSmart
```

Команда печатает QR-код в терминале. Откройте приложение Tuya Smart или
Smart Life, отсканируйте код и подтвердите вход. Если терминал не рисует
QR-код, укажите `--qr-file /tmp/tuya-qr.txt`: ссылка
`smartlife--qrLogin?token=...` будет записана в файл с правами `0600`,
а после входа удалена. Из неё можно сделать QR любым генератором.

Прокси для облачных запросов Tuya задаётся в `[tools.smart_home] proxy`.
Пусто — используется общий `[network] proxy`, `"direct"` — без прокси.
Если общий прокси не пропускает `apigw.iotbing.com`, укажите `direct`.

После подтверждения команда сама сохранит сессию, скачает устройства и
локальные ключи. Перезапустите `petrovichd` (супервизор поднимет его), чтобы
инструмент появился в текущем процессе: сессия читается при старте демона.
Повторный вход нужен, если ключи устарели или устройство перепривязали:

```bash
petrovichctl smart-home refresh   # обновить токен и ключи без QR
petrovichctl smart-home login     # полный вход по QR заново
petrovichctl smart-home logout    # удалить сессию и ключи с колонки
```

Полезные команды:

```bash
petrovichctl smart-home devices              # что найдено и поддерживается локально
petrovichctl smart-home discover             # найти устройства в сети сейчас
petrovichctl smart-home status "свет" --room "спальня"
petrovichctl smart-home set "лампа" --room "спальня" --brightness 40
petrovichctl smart-home set "кондиционер" --temperature 22
```

`login`, `refresh` и `devices` обращаются в облако; `status`, `set` и
`discover` работают локально при наличии сессии и ключей.

## Настройки

Секция необязательна: значения по умолчанию подходят для типовой квартиры.

```toml
[modules]
smart_home = true

[tools]
enabled = ["smart_home", "time", "timer", "volume"] # остальные по вкусу

[tools.smart_home]
# Пусто — локальная подсеть маршрута по умолчанию.
scan_subnet = "192.168.3.0/24"
# 0 — искать только по требованию, без фонового обхода.
scan_interval_s = 300
timeout_ms = 3000
cloud_timeout_ms = 20000
max_scan_hosts = 254
max_parallel = 32
# 3.1 передаёт часть данных без шифрования; выключите, если таких устройств нет.
allow_v31 = true
qr_timeout_s = 180
# Прокси только для облачных запросов Tuya; пусто — общий [network] proxy.
proxy = ""

[tools.smart_home.room_aliases]
зал = "Гостиная"

[tools.smart_home.aliases]
торшер = "Торшер у дивана"
```

Отключение:

- `[modules] smart_home = false` — инструмент и фоновый поиск не создаются;
- убрать `"smart_home"` из `[tools] enabled` — инструмент не показывается
  модели, но сессия и ключи остаются на диске;
- `petrovichctl smart-home logout` — удалить сессию и ключи.

## Голосовые команды

Петрович сам сопоставляет название, комнату и группу устройств:

- «выключи весь свет»;
- «включи лампу в спальне»;
- «сделай свет немного теплее»;
- «установи яркость на 40 процентов»;
- «какая температура в комнате?»;
- «выключи все розетки в гостиной».

Если под фразу подходят несколько устройств, инструмент не угадывает, а
возвращает уточняющий вопрос со списком. Псевдонимы из `aliases` и
`room_aliases` помогают, если в приложении устройства названы не по-русски
или слишком длинно.

Несколько действий за один ход выполняются параллельно штатным механизмом
инструментов. Каждое действие возвращает фактическое состояние: например,
«включено, яркость 41%», а не только «команда отправлена». Если устройство не
ответило или состояние не совпало, это видно в ответе.

## Безопасность

Политика проверяется в коде, а не в системном промпте. Модель не может
выбрать устройство по ID, отправить произвольный DP или обойти комнату.

- Разрешены по умолчанию: освещение, розетки, выключатели, климат
  (кондиционеры, обогреватели, термостаты).
- Только чтение: датчики температуры, влажности, движения, открытия,
  вибрации, протечки и присутствия.
- Полностью исключены: сигнализации, замки, камеры, дверные звонки, системы
  контроля доступа и прочие критичные категории.
- Неизвестная категория блокируется по умолчанию.
- Шлюзы и хабы не управляются; устройства Zigbee/BLE видны, только если
  локальный ключ и IP шлюза позволяют реально до них достучаться.
- Устройство без карты DP, без `local_key` или с облачным форматом состояния
  помечается как неподдерживаемое локально и не имитирует управление.

## Локальный протокол и ограничения

Поддержаны версии 3.1, 3.2/3.3, 3.4 и 3.5:

- 3.1 — частично без шифрования;
- 3.2/3.3 — AES-ECB, CRC, необязательный заголовок версии;
- 3.4 — AES-ECB с MD5-ключом;
- 3.5 — AES-GCM, handshake с nonce и HMAC, сессионный ключ;
- 3.3+ с `device22` — попытка с расширенным заголовком.

Автоопределение версии идёт по ответам устройства; IP и версия кэшируются в
`devices.json`. При ошибке связи Петрович заново ищет устройство в подсети и
повторяет команду один раз. Фоновый поиск пропавших устройств запускается не
чаще `scan_interval_s`.

Что заведомо не поддерживается:

- устройства, которые отдают состояние только через облако;
- камеры, замки, сигнализации и другие запрещённые категории — даже для
  чтения;
- произвольные DP и сырые команды;
- устройства за NAT, client isolation или в другой подсети без доступного
  IP — даже если аккаунт показывает их онлайн;
- точная семантика числовых enum-режимов, если устройство не сообщает
  строковые значения. Команда отправляется, но проверка может показать
  фактическое значение, а не запрошенное.

Облачного fallback для управления нет: если локальный интерфейс недоступен,
Петрович честно сообщает об ошибке, а не подменяет её облаком.

## Тесты

```bash
cargo test -p petrovich-tools smart_home
```

Покрыто: QR-вход и разбор сессии, подпись и расшифровка облачных запросов,
права `0600`, обнаружение подсети, handshake 3.5 и обмен 3.3/3.5 с mock-
устройством, разбор состояния, планирование команд, проверка фактического
состояния, псевдонимы/комнаты, уточнения и запрет опасных категорий.

## Диагностика

- `petrovichctl smart-home devices` — какие устройства сохранены, какие
  помечены неподдерживаемыми и почему.
- `petrovichctl smart-home discover` — принудительный поиск; полезен после
  смены IP или перезагрузки роутера.
- `petrovichctl smart-home status "имя"` — локальный запрос без управления.
- Журнал демона: `petrovichctl logs` (или `journalctl`), уровень `debug`
  показывает причины пропуска устройств, но не печатает ключи и токены.

Если после `login` устройств нет, проверьте, что аккаунт тот же, что в
приложении, и что устройства привязаны к дому. Если устройство есть, но
помечено «облако не сообщило карту DP», локальное управление для этой модели
недоступно — это ограничение устройства, а не ошибка авторизации.
